## This document is a self-written explanation of how a trasformer works from my memory

Input data to a transformer if non-numeric is converted to tokens (i did a character level encoding so each letter or symbol or number was and integer in sorted sequence) and these tokens or numeric data are converted to vectors so many values represent a single value of a feature. this is done to save more context on the value. the transformer also needs to know the position or feature-identity of that particular value in a feature so we add positional embeddings of feature embeddings either using fixed values or using a formula to calculate on the go with respect to the size of input. the latter is the proposed way in attention is all you need paper for scalability of input but i did indexes as pos emb since my size was fixed at 256. these token embeddings and positional embeddings are combined together to form one single embedding per value in a feature in an example row of data. data is batched with sequences. my batch size was 64 each with 256 length sequence.
For a translational task or task that has multiple types of data, encoder-decoder trasnformer is the better choice. a head is a part of transformer that has 3 smaller dimensional vectors called query, key and value. query and key are "i am looking for this" and "i am this" respectively. they both get multiplied with the input (input is passed through the linear layer to generate key and query tensors. my tensors were input 384 length) q @ k.transpose(-1,-2) in code to multply k and q. this forms the "attention matrix". divide by sqrt q or k size followed by softmax (which are same dimensions) to reduce by std dev. this matrix is then multiplied with a value matrix that says "if attended to, i give this" giving head output. multiheaded attetion involves dividing embedding size into multiple heads with full input. (i had 6 heads and 384 size input so each q,k,v was about 64 dimensional). a linear layer called projection is used to make sure the information of individual heads is mixed then followed by a computing feed-forward layer. residual connections are commonly used after each step to prevent vanishing gradients. dropouts can be used to prevent overfitting. Normalization is used before residuals to scale outputs. 
transformers can have multiple such layers in sequence, called "blocks". the output of the last layers gets a final normalization
Decoder has 'masking' meaning that we hide future tokens' weights so that the model does not learn from then since the goal of this is for each token to predict its next token sequentially with information from all previous tokens and itself. masking is done right before softmax setting upper triangular matrix to -inf so that softmax converts it to zero while still keeping total =1. cross-attention k and v from encoder, q from decoder. final layer norm on outputs > a linear layer lm_head converts to logits > softmax convert into probs for prediction
